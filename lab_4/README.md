# Лабораторна робота 4

## Події та стан у React

### Мета роботи

Навчитися обробляти дії користувача, змінювати стан компонента, передавати дані й функції через типізовані props та узгоджувати роботу кількох компонентів.

### Результат роботи

Виконайте три завдання в окремих React-проєктах на TypeScript:

1. Гра «Вгадай число» з обробкою натискання кнопки.
2. Список фруктів зі спільним станом і правильним підрахунком елементів.
3. Лічильник та форма введення з передаванням даних між компонентами.

Це вебзастосунки, які працюють у браузері. Сервер, база даних, маршрутизація, Context і `useEffect` для цих завдань не потрібні. Після перезавантаження сторінки стан повертається до початкових значень.

### Демо для ознайомлення

У папці [Демо-проєкти](Демо-проєкти/README.md) є чотири незалежні приклади з коментарями та власними інструкціями запуску: випадкова порада, вибір занять зі спільним підсумком, налаштування розміру тексту та форма назви. Кожен проєкт можна запускати окремо. Приклади демонструють потрібні механізми на іншій темі та не є готовими розв’язаннями завдань лабораторної.

## 2 Необхідні відомості

### 2.1 Обробник події

У React назви подій записують у camelCase: `onClick`, `onChange`, `onSubmit`. В обробник передають функцію:

```tsx
function HelpButton() {
  function handleClick() {
    window.alert('Кнопку натиснуто');
  }

  return <button type="button" onClick={handleClick}>Довідка</button>;
}
```

`onClick={handleClick}` означає «викликати після натискання». Запис `onClick={handleClick()}` викликає функцію вже під час рендеру і для такого обробника є помилкою.

### 2.2 Стан і повторний рендер

```tsx
import { useState } from 'react';

function CounterExample() {
  const [count, setCount] = useState(0);

  return (
    <button type="button" onClick={() => setCount(previous => previous + 1)}>
      Натискань: {count}
    </button>
  );
}
```

`count` — поточне значення, `setCount` — функція його оновлення. React отримує новий стан і повторно обчислює інтерфейс. Пряме присвоєння або звичайна локальна змінна не замінюють цей механізм.

Функція `previous => previous + 1` обчислює нове значення на основі попереднього. Сам `useState` викликайте на верхньому рівні компонента, а не всередині умови, циклу чи обробника. У події викликають `setCount`, а не створюють новий стан.

TypeScript визначає тип за початковим значенням: для `useState(0)` це `number`, для `useState('')` — `string`.

### 2.3 Props і спільні дані

Props — дані, які батьківський компонент передає дочірньому. Їх не змінюють у дочірньому компоненті. Для повідомлення про дію можна передати функцію через prop.

Якщо одні дані потрібні двом компонентам, стан розміщують у їхньому найближчому спільному батьківському компоненті. Це називається **підняттям стану**. Не створюйте незалежні копії тих самих даних у кількох компонентах.

Приклади нижче показують окремі прийоми. Повний інтерфейс і логіку завдань зберіть самостійно за кроками.

## 3 Завдання 1 Вгадай число

### Умова

Створіть програму з текстом «Вкажіть будь-яке число від 1 до 5» і кнопкою «Почати».

Після натискання:

1. Відкривається `prompt` із підказкою «Введіть ціле число від 1 до 5».
2. Програма перевіряє введення.
3. Для коректного введення комп’ютер генерує випадкове ціле число від `1` до `5` включно.
4. Вікно `alert` показує обидва числа та повідомлення «Ви вгадали!» або «Спробуйте ще раз».

Після закриття повідомлення можна знову натиснути «Почати». Кожна коректна спроба має генерувати нове число.

### Порядок виконання

1. У `lab4-guess/src/App.tsx` створіть заголовок і кнопку.
2. Усередині `App`, перед `return`, оголосіть `handleClick` та передайте його в `onClick`.
3. Додайте читання введення та перевірку його коректності.
4. Згенеруйте число комп’ютера, порівняйте числа через `===` та сформуйте результат.

Для перевірки введення використайте такий фрагмент **усередині `handleClick`**:

```tsx
const input = window.prompt('Введіть ціле число від 1 до 5');

if (input === null) return; // «Скасувати» — завершити спробу без повідомлення.

if (input.trim() === '') {
  window.alert('Ви не ввели число');
  return;
}

const userNumber = Number(input);

if (!Number.isInteger(userNumber) || userNumber < 1 || userNumber > 5) {
  window.alert('Потрібно ввести ціле число від 1 до 5');
  return;
}
```

`prompt` повертає рядок або `null`, а не число. Тому спочатку перевіряємо скасування, потім порожній текст і лише тоді перетворюємо значення через `Number`. Рядок із літерами перетвориться на `NaN`; перевірка `Number.isInteger` його відхилить, як і дробове число.

Генерування числа:

```tsx
const computerNumber = Math.floor(Math.random() * 5) + 1;
```

`Math.random()` повертає число від `0` включно до `1` невключно. Множення на `5` та `Math.floor` дають цілі значення `0–4`; додавання `1` зміщує їх до `1–5`.

Приклад тексту результату: «Ви вказали число: 5, число комп’ютера: 3. Спробуйте ще раз».

Стан тут не обов’язковий: результат показується в діалоговому вікні, а не зберігається в інтерфейсі. `prompt` і `alert` використовуються для навчального прикладу; поля та повідомлення на сторінці опрацюйте в завданні 3.

### Самоперевірка

- `1` та `5` приймаються; число комп’ютера завжди в межах `1–5`.
- `0`, `6`, `2.5` і `abc` відхиляються.
- Порожній рядок і рядок із пробілів не запускають спробу.
- Кнопка «Скасувати» не спричиняє помилки.
- Діалог відкривається після натискання, а не під час завантаження сторінки.

## 4 Завдання 2 Список фруктів і підняття стану

### Умова

Створіть компоненти `App`, `Fruits` та `FruitsCounter`. Спочатку список із трьох фруктів зберігається у стані `Fruits`, а лічильник показує фіксоване «Всього фруктів: 2». Підніміть стан до `App`, щоб список і кількість використовували одне джерело даних.

Після виконання на екрані має бути три фрукти та повідомлення «Всього фруктів: 3». Кількість потрібно обчислювати, а не записувати вручну.

### Крок 1 Створіть файли та тип даних

У проєкті `lab4-fruits` підготуйте:

```text
src/
├── App.tsx
├── Fruits.tsx
├── FruitsCounter.tsx
└── types.ts
```

У `types.ts` опишіть один фрукт:

```ts
export type Fruit = {
  id: number;
  fruitName: string;
};
```

У файлах, де цей тип використовується, додайте `import type { Fruit } from './types'`. Масив фруктів має тип `Fruit[]`.

### Крок 2 Відтворіть початкову ситуацію

У `Fruits` імпортуйте `useState` з `react` та оголосіть стан:

```tsx
const [fruits] = useState<Fruit[]>([
  { id: 1, fruitName: 'Яблуко' },
  { id: 2, fruitName: 'Груша' },
  { id: 3, fruitName: 'Слива' },
]);
```

Покажіть елементи списку в JSX:

```tsx
<ul>
  {fruits.map(fruit => (
    <li key={fruit.id}>{fruit.fruitName}</li>
  ))}
</ul>
```

`map` створює елемент інтерфейсу для кожного об’єкта. `key` допомагає React розрізняти елементи; використовуйте стабільний унікальний `id`.

У `FruitsCounter` тимчасово поверніть `<h2>Всього фруктів: 2</h2>`. Експортуйте обидва компоненти через `export default`, імпортуйте їх у `App` і відобразіть поруч. Переконайтеся, що кількість не відповідає списку.

### Крок 3 Підніміть стан до App

1. Перенесіть оголошення `useState` з масивом до `App` разом із потрібними імпортами.
2. Видаліть власний стан із `Fruits` і непотрібний імпорт `useState` у цьому файлі.
3. Нехай `Fruits` отримує масив через props. Перед функцією компонента оголосіть тип, а її параметр запишіть так:

```tsx
type FruitsProps = { fruits: Fruit[] };

// Заголовок функції; збережіть її JSX зі списком.
// function Fruits({ fruits }: FruitsProps) { ... }
```

4. Аналогічно опишіть `FruitsCounterProps` із полем `fruits: Fruit[]` для компонента `FruitsCounter`.
5. У JSX `App` передайте масив обом компонентам:

```tsx
<Fruits fruits={fruits} />
<FruitsCounter fruits={fruits} />
```

6. У `FruitsCounter` замініть фіксоване число на `{fruits.length}`.

Назва перед `=` у `fruits={fruits}` — назва prop, значення в дужках — змінна з `App`. Окремий стан для кількості не потрібен: вона обчислюється з масиву.

### Самоперевірка

- Початкові три об’єкти дають три елементи списку та кількість `3`.
- Тимчасово додайте четвертий об’єкт з унікальним `id` у початковий масив і перезавантажте сторінку: кількість має стати `4` без змін у `FruitsCounter`.
- Тимчасово задайте порожній масив: має відобразитися `0`.
- Поверніть три початкові фрукти. Не створюйте дубль масиву в `FruitsCounter`.

Перезавантаження потрібне для перевірки зміненого початкового значення: під час редагування коду середовище розробки може зберігати поточний стан компонента.

## 5 Завдання 3 Лічильник і введення тексту

### Умова

У проєкті `lab4-input` створіть `App.tsx`, `Counter.tsx` і `TextInput.tsx`.

**Counter:**

- початкове значення — `0`;
- `Increase` додає `1`, `Decrease` віднімає `1`;
- коли значення менше `0`, поруч з ним показано «Counter can't be negative»;
- після повернення до `0` або додатного числа повідомлення зникає.

У цьому завданні від’ємні значення допускаються для демонстрації умовного повідомлення. Не замінюйте цю поведінку блокуванням кнопки на нулі.

**TextInput:**

- містить підписане текстове поле та кнопку `Submit`;
- введення тексту одразу оновлює поле;
- текст під формою змінюється лише після `Submit`;
- надсилання порожнього або заповненого лише пробілами поля не підтверджується: покажіть зрозуміле повідомлення.

**App:**

- показує обидва компоненти;
- показує «Number of characters: N», де `N` оновлюється під час введення, ще до натискання `Submit`.

### Крок 1 Реалізуйте Counter

Використайте локальний `useState(0)`. Для зміни значення застосуйте функції оновлення:

```tsx
// Фрагменти для відповідних обробників:
setCount(previous => previous + 1);
setCount(previous => previous - 1);
```

Кожен виклик належить своїй кнопці; не розміщуйте обидва в одному обробнику. У JSX додайте умовне повідомлення:

```tsx
{count < 0 && <p role="status">Counter can't be negative</p>}
```

Якщо умова істинна, React показує абзац; якщо ні — не показує. Кнопкам задайте `type="button"`.

### Крок 2 Розподіліть стан між App і TextInput

Потрібно розрізняти два значення:

| Значення | Де зберігати | Коли змінюється |
| --- | --- | --- |
| `text` — поточний текст поля | `App` | Під час введення |
| `submittedText` — підтверджений текст | `TextInput` | Після коректного `Submit` |

Поточний текст потрібен і полю, і лічильнику символів у `App`, тому зберігайте його в `App`. Підтверджений текст потрібен лише під формою, тому він залишається локальним станом `TextInput`.

У `App` додайте `const [text, setText] = useState('')`. Передайте дані й функцію дочірньому компоненту:

```tsx
<TextInput value={text} onTextChange={setText} />
<p>Number of characters: {text.length}</p>
```

Обидва елементи розміщуйте всередині спільного JSX-контейнера разом із `Counter`. Не забудьте імпортувати компоненти та `useState`.

### Крок 3 Опишіть props і кероване поле

У `TextInput.tsx` оголосіть:

```tsx
type TextInputProps = {
  value: string;
  onTextChange: (text: string) => void;
};
```

Функція компонента має отримувати `{ value, onTextChange }: TextInputProps`. Тип `onTextChange` означає функцію, якій передають рядок; її результат компонент не використовує.

Додайте в JSX поле:

```tsx
<label>
  Текст:
  <input
    value={value}
    onChange={event => onTextChange(event.currentTarget.value)}
  />
</label>
```

Поле кероване: показує значення `value`, а після введення повідомляє батьківський компонент через `onTextChange`. `setText` у `App` оновлює стан, і новий текст повертається в поле через props.

Для стрілкової функції безпосередньо в JSX TypeScript визначить тип `event` автоматично. Якщо винесете обробник в окрему функцію, використайте:

```tsx
import type { ChangeEvent } from 'react';

// Функція всередині TextInput:
function handleChange(event: ChangeEvent<HTMLInputElement>) {
  onTextChange(event.currentTarget.value);
}
```

Тоді замініть inline-обробник на `onChange={handleChange}`. Оберіть один варіант.

### Крок 4 Реалізуйте Submit

1. У `TextInput` створіть локальні стани `submittedText` і `error`, обидва з початковим `''`.
2. Обгорніть поле й кнопку у `<form>`. Кнопці задайте `type="submit"`.
3. На форму додайте `onSubmit`. Першою дією викличте `event.preventDefault()`, щоб браузер не перезавантажував сторінку.
4. Якщо `value.trim() === ''`, задайте повідомлення в `error` і завершіть обробник через `return`, не змінюючи `submittedText`.
5. Інакше очистьте помилку та скопіюйте `value` у `submittedText`.
6. Під формою покажіть `submittedText`, а повідомлення про помилку — лише коли `error` не порожній, наприклад у `<p role="alert">`.

Початок обробника можна записати безпосередньо в JSX:

```tsx
<form onSubmit={event => {
  event.preventDefault();
  // Тут додайте перевірку value й оновлення станів.
}}>
  {/* Тут розмістіть поле та кнопку Submit. */}
</form>
```

Не прив’язуйте всю логіку лише до `onClick` кнопки: `onSubmit` форми також підтримує надсилання клавішею Enter.

У цій роботі кількість визначайте через `text.length`. Для звичайних українських і латинських літер це очікувана кількість символів; деякі emoji та комбіновані символи можуть враховуватися інакше, оскільки JavaScript рахує одиниці UTF-16. Окремий підрахунок видимих Unicode-символів не потрібен.

### Самоперевірка

- На початку лічильник і кількість символів дорівнюють `0`.
- Після `Decrease` з нуля видно `-1` та повідомлення; після `Increase` до нуля повідомлення зникає.
- Введення `React` одразу показує `Number of characters: 5`.
- Після `Submit` під формою видно `React` без перезавантаження сторінки.
- Якщо змінити поле на `React TS`, кількість стає `8`, але підтверджений текст залишається `React` до наступного `Submit`.
- Enter надсилає форму так само, як кнопка.
- Порожнє введення й пробіли спричиняють повідомлення, не стираючи попередній підтверджений текст.
- Робота з текстом не скидає числовий лічильник, а натискання його кнопок не змінює текст.

### Додаткове завдання

- Додайте до `Counter` кнопку `Reset`, яка встановлює `0`.
- Обмежте введення 50 одиницями довжини рядка через `maxLength={50}` на `<input>` і покажіть індикатор `{value.length}/50`.

## 6 Завершення роботи

У кожному з трьох проєктів виконайте:

```bash
npm run build
npm run lint
```

Використовуйте окремий термінал у папці відповідного проєкту або зупиніть сервер через `Ctrl+C`. Виправте помилки типів, неправильні імпорти й попередження про невикористаний код. У стандартному шаблоні React + TypeScript команда `build` перевіряє TypeScript і створює збірку в `dist`.

Типові причини проблем:

- не знайдено компонент — перевірте шлях імпорту, регістр назви файла та `export default`;
- не знайдено `useState` — додайте імпорт із `react`;
- імпортований тип потрібно позначити як type-only — використайте `import type`;
- поле не редагується — перевірте `value` та оновлення стану через `onChange`;
- форма перезавантажує сторінку — перевірте `preventDefault()` в `onSubmit`;
- кількість фруктів або символів не змінюється — не записуйте її константою і не дублюйте відповідні дані в незалежному стані.

Підготуйте вихідні файли трьох проєктів із `package.json` і `package-lock.json`. Для архіву не додавайте `node_modules` і `dist`: залежності відновлюються через `npm install`, збірка — через `npm run build`. Додайте короткий опис запуску та знімки екрана результатів і перевірок.
