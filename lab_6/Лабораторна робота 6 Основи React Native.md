# Лабораторна робота №6. Основи React Native

## Мета роботи

Створити перший екран мобільного застосунку на React Native з використанням TypeScript. Навчитися складати інтерфейс із компонентів, оформлювати його через `StyleSheet`, враховувати безпечні межі екрана й прокручувати довгий вміст, залишаючи підвал видимим.

## Що має працювати наприкінці

Екран невеликого бістро **Little Lemon** містить шапку з назвою, привітальний текст, довший опис закладу та підвал із поточним роком. Середня частина екрана прокручується, а шапка й підвал залишаються на місці. Вміст не заходить під виріз, системний рядок стану та нижній індикатор телефона. Усі власні стилі зібрані в `StyleSheet.create`.

## Підготовка

Потрібні Node.js, редактор коду та телефон з Expo Go або емулятор Android/iOS. Команди нижче виконують у терміналі. Термінал має бути відкритий у папці, де ви хочете зберегти проєкт.

```bash
npx create-expo-app@latest little-lemon --template blank-typescript
cd little-lemon
npx expo install react-native-safe-area-context
npx expo start
```

Перша команда створює порожній проєкт Expo з TypeScript. `cd` переходить у його папку. `npx expo install` добирає версію бібліотеки, сумісну з установленою версією Expo. Остання команда запускає сервер розробки та показує QR-код. На телефоні відкрийте застосунок через Expo Go; телефон і комп’ютер мають бути в одній мережі. Для емулятора користуйтеся підказками у терміналі. Не закривайте термінал під час роботи із застосунком.

Якщо QR-код не відкриває проєкт, перевірте спільну мережу, дозвіл брандмауера та чи працює сервер. Після зміни коду Expo зазвичай оновлює екран автоматично. Помилки компіляції показуються в терміналі та застосунку.

У шаблоні `blank-typescript` головний файл — `App.tsx`. Розширення `.tsx` означає TypeScript-файл із JSX-розміткою. Файл `index.ts` реєструє застосунок; зазвичай його не потрібно змінювати. `package.json` містить команди запуску й залежності, `app.json` — назву та параметри Expo, `assets/` — локальні ресурси. Папка `node_modules/` створюється після встановлення залежностей і не призначена для ручного редагування.

## Теоретичні відомості

### React Native і компоненти

React Native дає змогу описувати мобільний інтерфейс компонентами React. Компонент — це функція, яка повертає розмітку екрана. Ім’я власного компонента пишуть з великої літери. Компоненти можна вкладати один в один, щоб побудувати цілий екран.

У вебсторінці текст часто розміщують у `<p>`, а блок — у `<div>`. У React Native використовують інші базові елементи:

| Компонент | Призначення |
| --- | --- |
| `View` | Групує елементи та задає структуру екрана. |
| `Text` | Показує текст. Текст потрібно розміщувати всередині `Text`, а не безпосередньо у `View`. |
| `ScrollView` | Дозволяє прокручувати вміст, який не вміщується на екрані. |
| `SafeAreaView` | Розміщує вміст у межах видимої частини екрана. У цій роботі його беремо з `react-native-safe-area-context`. |

Наприклад, простий компонент:

```tsx
import { Text, View } from 'react-native';

export function Greeting() {
  return (
    <View>
      <Text>Вітаємо!</Text>
    </View>
  );
}
```

`import` підключає компоненти бібліотеки. `export` дозволяє імпортувати вашу функцію з іншого файлу. JSX схожий на HTML, але це не HTML: набір елементів і правила стилізації відрізняються. `return (...)` описує те, що буде показано на екрані.

### Властивості компонентів і TypeScript

Властивості, або `props`, передають дані дочірньому компоненту. У TypeScript їхню форму можна описати типом:

```tsx
import { Text } from 'react-native';

type SectionTitleProps = {
  title: string;
};

export function SectionTitle({ title }: SectionTitleProps) {
  return <Text>{title}</Text>;
}

// Використання в іншому компоненті:
// <SectionTitle title="Наше меню" />
```

Тип `string` означає текст. Якщо випадково передати число замість назви, редактор і компілятор TypeScript повідомлять про невідповідність ще до запуску. Фігурні дужки `{title}` у JSX підставляють значення змінної. Для цієї роботи можна передавати текст через `props` або записати його безпосередньо в компонентах.

### Стилі та Flexbox

У React Native стиль — це JavaScript-об’єкт. Назви властивостей пишуть у `camelCase`: `backgroundColor`, `fontSize`, `paddingHorizontal`. Числа для розмірів записують без `px`; React Native працює з незалежними від щільності пікселями. Є відмінності від CSS браузера: не використовують селектори на зразок `.card`, а стиль передають через властивість `style`.

```tsx
import { StyleSheet, Text, View } from 'react-native';

export function Notice() {
  return (
    <View style={styles.box}>
      <Text style={styles.message}>Сьогодні ми відкриті</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  box: {
    backgroundColor: '#EDEFEE',
    padding: 16,
  },
  message: {
    color: '#333333',
    fontSize: 18,
  },
});
```

`StyleSheet.create` групує стилі з промовистими назвами та допомагає перевіряти властивості у TypeScript. Стилі не успадковуються так само, як CSS у браузері: колір тексту потрібно задати самому `Text` або його текстовому предку.

React Native використовує Flexbox для розташування елементів. На відміну від типового CSS у браузері, напрямок за замовчуванням — **стовпчик** (`column`): елементи йдуть згори вниз. `flex: 1` означає «займи доступний простір». Це важливо для середньої прокручуваної частини: вона заповнить місце між шапкою та підвалом, не виштовхуючи їх за межі екрана.

Для кольорів Little Lemon можна використати невелику палітру: темно-зелений `#495E57`, світлий `#EDEFEE`, темний текст `#333333`, теплий акцент `#EE9972` і білий `#FFFFFF`. Перевіряйте контраст: світлий текст на світлому тлі читати важко.

### Безпечна зона та прокручування

У різних телефонів є виріз камери, рядок стану та системна область унизу. `SafeAreaProvider` надає відомості про ці межі, а `SafeAreaView` із пакета `react-native-safe-area-context` додає відповідні відступи. Не імпортуйте `SafeAreaView` із `react-native`: для нових проєктів слід використовувати бібліотеку безпечних зон.

`ScrollView` потрібен для невеликого обсягу довгого статичного вмісту. Він створює всі дочірні елементи одразу. Для великих динамічних списків краще застосовувати `FlatList` — це тема наступної роботи. Прокручування працює надійно, коли батьківський контейнер має обмежену висоту; у цьому екрані таку висоту забезпечує `flex: 1` у кореневому контейнері.

Властивість `style` у `ScrollView` оформлює зовнішню прокручувану область, а `contentContainerStyle` — контейнер усередині неї. Відступ унизу довгого тексту зручно задати саме через `contentContainerStyle`, щоб останній абзац не прилипав до краю. Властивість `indicatorStyle="white"` задає світлий індикатор прокручування в iOS; на Android його вигляд може відрізнятися.

## Виконання роботи

### Крок 1. Підготуйте структуру екрана

Створіть папку `components/` і файли `LittleLemonHeader.tsx`, `WelcomeScreen.tsx`, `LittleLemonFooter.tsx`. Головний `App.tsx` поєднає ці частини. Назви можна вибрати інші, але зберігайте принцип: один компонент відповідає за одну зрозумілу частину екрана.

У `App.tsx` підключіть `SafeAreaProvider` і `SafeAreaView`:

```tsx
import { SafeAreaProvider, SafeAreaView } from 'react-native-safe-area-context';
import { StyleSheet } from 'react-native';

export default function App() {
  return (
    <SafeAreaProvider>
      <SafeAreaView style={styles.screen} edges={['top', 'bottom']}>
        {/* Тут будуть шапка, вміст і підвал. */}
      </SafeAreaView>
    </SafeAreaProvider>
  );
}

const styles = StyleSheet.create({
  screen: { flex: 1, backgroundColor: '#495E57' },
});
```

`edges` перелічує краї, для яких потрібно врахувати безпечну зону. Це фрагмент каркаса, а не готовий застосунок: замініть коментар власними компонентами. Перевірте, що у JSX є один кореневий елемент — тут це `SafeAreaProvider`.

### Крок 2. Створіть шапку та підвал

У `LittleLemonHeader.tsx` покажіть назву закладу та короткий підзаголовок. Використайте `View` для блоку й окремі `Text` для рядків. Надайте їм стилі. Можна почати з прикладу `Greeting` вище, замінивши назву та додавши другий `Text`.

У `LittleLemonFooter.tsx` покажіть рядок на зразок `© 2026 Little Lemon`, але отримуйте рік автоматично:

```tsx
const year = new Date().getFullYear();
// Усередині <Text>: © {year} Little Lemon
```

`new Date()` створює об’єкт поточної дати, `getFullYear()` повертає рік, а `{year}` вставляє його в JSX. Подбайте про контрастний колір тексту та зручні внутрішні відступи.

Після створення компонентів імпортуйте їх у `App.tsx` і розмістіть шапку першою, підвал останнім. Не застосовуйте `position: 'absolute'` для підвалу: він може перекрити текст або системну область. Його фіксоване місце забезпечить структура екрана після кроку 4.

### Крок 3. Створіть привітальний вміст

У `WelcomeScreen.tsx` додайте заголовок «Ласкаво просимо до Little Lemon» і кілька абзаців про бістро: які страви воно пропонує, чим вирізняється, коли або для кого працює. Текст має бути достатньо довгим, щоб на невеликому екрані з’явилася потреба прокручувати його. Оформіть заголовок і основний текст по-різному: розміром, товщиною шрифту, кольором та відступами.

Наприклад, основу можна побудувати так:

```tsx
import { Text, View } from 'react-native';

export function WelcomeScreen() {
  return (
    <View>
      <Text>Ласкаво просимо до Little Lemon</Text>
      <Text>Тут розмістіть власний опис закладу.</Text>
    </View>
  );
}
```

Це лише початок: доповніть вміст, додайте стилі й перевірте, як він виглядає на телефоні. Не копіюйте один абзац багато разів лише для штучного збільшення висоти: напишіть кілька змістовних частин.

### Крок 4. Зробіть прокручуваною тільки середину

Розмістіть `WelcomeScreen` усередині `ScrollView`, а шапку та підвал — **поза** ним:

```tsx
<LittleLemonHeader />
<ScrollView
  style={styles.scroll}
  contentContainerStyle={styles.scrollContent}
  indicatorStyle="white"
>
  <WelcomeScreen />
</ScrollView>
<LittleLemonFooter />
```

Для цього додайте `ScrollView` до імпорту з `react-native`. У `StyleSheet` для `scroll` вкажіть `flex: 1`, а для `scrollContent` — внутрішні відступи, зокрема `paddingBottom`. Тоді середня область займе вільне місце між шапкою і підвалом. Якщо прокрутка не працює, перевірте наявність довгого тексту, `flex: 1` у кореневого `SafeAreaView` та прокручуваної області.

Прокрутіть текст до кінця. Останній рядок має повністю читатися, а підвал — залишатися видимим. У iOS на темному тлі можна побачити світлий індикатор; на Android не вимагайте ідентичного вигляду індикатора.

### Крок 5. Упорядкуйте стилі

Перенесіть стилі з довгих об’єктів усередині `style={{ ... }}` у `StyleSheet.create` відповідного файлу. Наприклад, замість:

```tsx
<Text style={{ color: '#FFFFFF', fontSize: 20 }}>Назва</Text>
```

використайте:

```tsx
<Text style={styles.title}>Назва</Text>

const styles = StyleSheet.create({
  title: { color: '#FFFFFF', fontSize: 20 },
});
```

Кожен компонент може мати свій `styles` у власному файлі. Назви `title`, `footer`, `scrollContent` пояснюють роль стилю. Перевірте, що текст не зливається з тлом і що на вузькому екрані немає горизонтального обрізання. Не задавайте всьому екрану фіксовану висоту в пікселях: вона відрізняється між пристроями.

### Крок 6. Перевірте застосунок

На екрані телефона перевірте короткий і довгий вміст: тимчасово скоротіть опис до одного абзацу, потім поверніть усі абзаци. В обох випадках підвал має бути на нижньому краю доступної області; при довгому вмісті прокручується лише середина. Перевірте портретну орієнтацію, читабельність і безпечні відступи.

Окремо запустіть перевірку TypeScript із папки проєкту:

```bash
npx tsc --noEmit
```

`tsc` перевіряє типи, а `--noEmit` означає «не створювати JavaScript-файли». Відсутність повідомлень про помилки та код завершення 0 означають успішну перевірку типів. Ця команда не замінює запуск на телефоні: вона не покаже помилки компонування інтерфейсу.

## Демонстраційний проєкт

Поруч із цим файлом є папка `rn-first-screen-demo/` — готовий приклад екрана **міського музею**. Він використовує ті самі базові механізми: `View`, `Text`, власні компоненти, `StyleSheet`, безпечні межі, прокручувану середину та підвал. Тема й зміст відрізняються від вашого завдання. Прочитайте коментарі в `App.tsx` і файлах `components/`, запустіть приклад за інструкцією у його `README.md`, змініть один текст або колір та простежте за результатом.

## Типові помилки

- **Текст усередині `View` без `Text`**: кожен текстовий фрагмент має бути вкладений у `Text`.
- **Прокручується підвал**: `Footer` помилково розміщений усередині `ScrollView`; перенесіть його після закривального `</ScrollView>`.
- **Підвал перекриває вміст**: приберіть абсолютне позиціонування; використайте кореневий контейнер і прокручувану середину з `flex: 1`.
- **Вміст під системними елементами**: перевірте `SafeAreaProvider`, `SafeAreaView` та імпорт із `react-native-safe-area-context`.
- **Немає прокрутки**: перевірте довжину вмісту та `flex: 1` у батьківському контейнері й `ScrollView`.
- **TypeScript не знаходить компонент**: перевірте точне ім’я файлу, шлях імпорту, `export` та великі/малі літери.

Поясніть структуру файлів, роль кожного компонента, безпечної зони, `flex: 1` і `StyleSheet`. Будьте готові відповісти на контрольні запитання та внести невелику зміну в код під час демонстрації — наприклад, змінити колір підвалу, текст шапки або відступ у прокручуваній області — і пояснити результат.

Контрольні запитання:

1. Чим `View` і `Text` відрізняються від `div` і звичайного тексту у браузері?

5. Чому підвал розміщено поза `ScrollView`?
6. Чим відрізняються `style` і `contentContainerStyle` у `ScrollView`?
