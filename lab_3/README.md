# Лабораторна робота 3

## Основи React

### Мета роботи

Навчитися створювати React-застосунок на TypeScript, розділяти сторінку на компоненти, імпортувати й експортувати їх, передавати дані через props та оформлювати інтерфейс за допомогою CSS.

### Результат роботи

Створіть сторінку «Мої дисципліни». Вона повинна містити привітання з вашим ім’ям, прізвищем і групою та щонайменше чотири картки дисциплін. Картки мають використовувати один компонент, але отримувати різні дані. Назву, опис, кількість кредитів і відомості про викладача потрібно передавати через типізовані props.

Виконайте чотири основні завдання послідовно в одному проєкті. Додаткове завдання з кнопкою вибору дисципліни є необов’язковим.

Для виконання потрібні базові знання HTML, CSS, функцій і об’єктів JavaScript. Необхідні конструкції TypeScript пояснено безпосередньо перед їх використанням.

### Демо для самостійного дослідження

У папці [Демо-проєкт Campus Clubs](Демо-проєкт%20Campus%20Clubs/README.md) міститься готовий каталог студентських гуртків. Він показує компоненти, типізовані props, обов’язкові й необов’язкові поля, CSS та незалежний локальний стан карток на іншій темі. У коді є пояснювальні коментарі, а в README демо — порядок запуску, читання файлів і невеликі експерименти. Досліджуйте його паралельно з відповідними завданнями; власна робота має залишатися сторінкою дисциплін.

Для першого знайомства з компонентами можна почати з [двох базових прикладів JS і TS](Базові%20приклади%20JS%20і%20TS/README.md): це однакова сторінка з двома простими лічильниками. Порівняння показує, що саме TypeScript додає до JavaScript-коду, не змінюючи поведінки програми.

## 1 Підготовка до роботи

### 1.1 Потрібні інструменти

Підготуйте:

- Visual Studio Code або інший редактор коду;
- сучасний браузер;
- Node.js підтримуваної LTS-версії та npm;
- доступ до інтернету для початкового завантаження пакетів.

Node.js запускає інструменти розробки на комп’ютері. npm встановлює бібліотеки та виконує команди проєкту. Сам інтерфейс цієї роботи працюватиме в браузері, а не в терміналі Node.js.

Якщо Node.js ще не встановлено, завантажте інсталятор LTS з [офіційної сторінки Node.js](https://nodejs.org/en/download), виконайте встановлення та перезапустіть редактор. Використовуйте версію, сумісну з актуальним Vite; якщо npm повідомляє про несумісний `engine`, оновіть Node.js до підтримуваної LTS.

У VS Code виберіть **Terminal → New Terminal** і введіть команди по черзі:

```bash
node --version
npm --version
```

Кожна команда повинна вивести номер версії. Якщо з’явилося повідомлення, що команду не знайдено, спочатку перевірте встановлення Node.js і перезапустіть термінал.

### 1.2 React у цій роботі

React — бібліотека для створення інтерфейсів із компонентів. Компонент описує окрему частину сторінки: привітання, картку дисципліни, кнопку чи цілий екран. З невеликих компонентів можна скласти більший.

У цій роботі використовується React для вебу: результат відображає бібліотека React DOM у браузері. React Native використовує ті самі базові поняття компонентів, props і стану, але має інші елементи інтерфейсу. Наприклад, замість вебелементів `div` і `p` у React Native використовують `View` і `Text`. Створений тут Vite-проєкт не є Android- чи iOS-застосунком.

### 1.3 Створення проєкту

Виберіть на комп’ютері папку для лабораторних робіт і відкрийте її у VS Code через **File → Open Folder**. У вбудованому терміналі виконайте:

```bash
npm create vite@latest lab3 -- --template react-ts
```

Команда створює всередині поточної папки нову папку `lab3` із проєктом React + TypeScript. `react-ts` — назва шаблону; `--` передає наступні параметри засобу створення проєкту. Якщо npm запитає дозвіл встановити `create-vite`, підтвердьте його. Якщо з’явиться запит про автоматичне встановлення залежностей і запуск, відмовтеся: ці дії виконайте наступними командами.

Не запускайте команду в папці, яка вже містить іншу роботу з назвою `lab3`. Виберіть іншу батьківську папку або іншу вільну назву проєкту. Не погоджуйтеся на видалення наявних файлів.

Перейдіть до створеного проєкту, встановіть залежності та запустіть сервер розробки:

```bash

npm install
npm run dev
```

Дочекайтеся завершення кожної команди перед введенням наступної. Після останньої команди термінал залишиться зайнятим — це нормально, сервер продовжує працювати. Відкрийте в браузері адресу, зазначену біля `Local`, зазвичай `http://localhost:5173`. Якщо порт зайнятий, адреса може бути іншою.

Відкрийте папку `lab3` як папку проєкту у VS Code. Якщо через це попередній сервер зупинився, знову виконайте `npm run dev` у терміналі цієї папки.

Зберігайте зміни у файлах через `Ctrl+S` у Windows/Linux або `Cmd+S` у macOS. Сервер розробки зазвичай одразу передає їх у браузер. Для зупинки сервера натисніть `Ctrl+C` у його терміналі.

### 1.4 Будова проєкту

Основні файли після створення:

```text
lab3/
├── public/
├── src/
│   ├── App.tsx
│   ├── App.css
│   ├── index.css
│   └── main.tsx
├── index.html
├── package.json
├── package-lock.json
├── tsconfig.json
├── tsconfig.app.json
└── vite.config.ts
```

Шаблон може містити й інші файли конфігурації та стартові зображення. Їх не потрібно видаляти.

- `src/App.tsx` — головний компонент сторінки, який ви змінюватимете.
- `src/main.tsx` — початкова точка виконання клієнтського коду. Вона підключає `App` до HTML-сторінки та імпортує загальні стилі.
- `src/index.css` — загальні стилі, наприклад шрифт, колір тла та відступи.
- `src/App.css` — стилі, які можна підключити до `App`. У цій роботі всі потрібні стилі розміщуватимуться в `index.css`.
- `index.html` — HTML-документ із контейнером `id="root"` і підключенням `src/main.tsx`.
- `package.json` — список залежностей і команд проєкту.
- `package-lock.json` — точні версії встановлених залежностей для відтворюваного встановлення.
- `tsconfig*.json` — налаштування перевірки TypeScript; `vite.config.ts` — налаштування Vite. Залиште конфігурацію шаблону.
- `node_modules` — бібліотеки, які створила команда `npm install`. Не редагуйте їх вручну.

Розширення `.tsx` означає, що файл містить TypeScript і може містити JSX. Файл із JSX не слід називати `.ts`. Для звичайних функцій або типів без JSX достатньо `.ts`.

Не запускайте `App.tsx` командою `node App.tsx` і не відкривайте `index.html` подвійним клацанням. Цей проєкт запускається через `npm run dev`: Vite обробляє TypeScript, JSX, імпорти та стилі перед передаванням у браузер.

У кореневому `index.html` змініть мову документа на `<html lang="uk">`, а текст усередині `<title>...</title>` — на `Мої дисципліни`. Мова допомагає правильно озвучувати український текст, а назва з’являється на вкладці браузера. Решту вмісту, зокрема контейнер `root`, налаштування `viewport` і підключення скрипту, залиште без змін.

## 2 Завдання 1 Створення першого компонента

### Крок 1 Замініть стартовий екран

Відкрийте `src/App.tsx`, видаліть його стартовий вміст і вставте:

```tsx
function Heading() {
  return <h1>Привіт, Олено Коваль! Група ІПЗ-21</h1>;
}

export default function App() {
  return (
    <main className="page">
      <Heading />
    </main>
  );
}
```

Змініть ім’я, прізвище та групу на власні. Збережіть файл і перевірте браузер.

Тут `Heading` і `App` — дві окремі функції-компоненти. `Heading` повертає опис заголовка, а `App` розміщує його в основній області сторінки. Запис `<Heading />` означає використання компонента. React викликає його під час побудови інтерфейсу. Не замінюйте цей запис самостійним викликом `Heading()`.

Обидві функції оголошені на верхньому рівні файлу: `Heading` не знаходиться всередині тіла `App`. Вкладати можна JSX-елементи, але не потрібно вкладати оголошення компонентів у функції інших компонентів.

Власні компоненти називають із великої літери: `Heading`, `App`, `Subject`. Назви на кшталт `main`, `h1`, `p` починаються з малої літери та позначають вбудовані браузерні елементи.

### Крок 2 Задайте початкові стилі

Замініть увесь вміст `src/index.css` на:

```css
:root {
  font-family: system-ui, sans-serif;
  line-height: 1.5;
  color: #252125;
  background-color: #f5f3f5;
}

* {
  box-sizing: border-box;
}

body {
  margin: 0;
}

.page {
  max-width: 1000px;
  margin: 0 auto;
  padding: 24px;
}

h1 {
  color: #501649;
}
```

Переконайтеся, що `src/main.tsx` містить `import './index.css'` або такий самий імпорт у подвійних лапках. Решту цього файлу залиште без змін. У новому `App.tsx` немає імпорту `App.css`, тому старі стилі з `App.css` не впливають на результат.

`box-sizing: border-box` включає внутрішні відступи й рамку в задану ширину елемента. `.page` обмежує ширину вмісту, `margin: 0 auto` центрує його, а `padding` віддаляє текст від країв. На вузькому екрані блок займає доступну ширину.

### Крок 3 Розберіться з JSX

JSX — синтаксис опису інтерфейсу, схожий на HTML, який використовується в JavaScript і TypeScript. React отримує з нього опис елементів, а React DOM створює та оновлює відповідні вузли сторінки.

Основні правила:

1. Закривайте теги: `<p>Текст</p>` або `<Heading />`.
2. Повертайте сусідні елементи в одній обгортці, наприклад `<main>...</main>`. Якщо додатковий HTML-елемент не потрібен, використовуйте фрагмент `<>...</>`.
3. Для CSS-класу пишіть `className`, а не `class`.
4. JavaScript-вирази вміщуйте у фігурні дужки: `<p>{2 + 3}</p>` покаже `5`.
5. Для багаторядкового JSX ставте `(` одразу після `return`, як у прикладі `App`. Не переносіть вираз на новий рядок після окремого `return`: автоматичне вставлення крапки з комою може завершити повернення раніше.

Текст `<p>firstName</p>` відображає слово `firstName`. Запис `<p>{firstName}</p>` відображає значення змінної з таким ім’ям. Фігурні дужки потрібні саме для переходу від тексту JSX до виразу.

У сучасному React-шаблоні не потрібно додавати `import React from 'react'` лише заради JSX: потрібне перетворення вже налаштоване. Конкретні функції, наприклад `useState`, імпортують окремо тоді, коли використовують.

Правила JSX також наведено в [документації React](https://react.dev/learn/writing-markup-with-jsx).

### Перевірка завдання 1

У браузері має бути один заголовок із вашими даними. Змініть текст у `Heading` і переконайтеся, що після збереження результат оновився. Поясніть, яку роль виконують `Heading`, `App`, `return` і `<Heading />`.

## 3 Завдання 2 Компонент в окремому файлі

### Крок 1 Створіть файл компонента

У панелі файлів VS Code натисніть правою кнопкою на `src`, виберіть **New Folder** і створіть папку `components`. Усередині неї через **New File** створіть `Heading.tsx`.

У `src/components/Heading.tsx` розмістіть:

```tsx
export default function Heading() {
  return <h1>Привіт, Олено Коваль! Група ІПЗ-21</h1>;
}
```

Залиште тут власні дані. Слова `export default` роблять компонент доступним для імпорту з інших файлів як основний експорт цього модуля.

### Крок 2 Підключіть компонент

Замініть вміст `src/App.tsx` на:

```tsx
import Heading from './components/Heading';

export default function App() {
  return (
    <main className="page">
      <Heading />
    </main>
  );
}
```

У `App.tsx` більше не повинно бути оголошення `function Heading`. Компонент тепер оголошений в одному місці та імпортований там, де його використовують.

У шляху `./components/Heading` крапка означає поточну папку файлу `App.tsx`, тобто `src`. Далі вказано папку `components` і назву файлу. У цьому Vite-проєкті можна не писати розширення `.tsx` в імпорті. Регістр літер має збігатися: `Heading` і `heading` не слід використовувати як взаємозамінні назви.

### Крок 3 Порівняйте два способи експорту

Компонент можна експортувати за замовчуванням або як іменований експорт. Приклади нижче — альтернативи, а не два фрагменти, які потрібно одночасно додати у файл.

Експорт за замовчуванням:

```tsx
// Оголошення у файлі компонента
export default function Heading() {
  return <h1>Мої дисципліни</h1>;
}

// Імпорт в іншому файлі
import Heading from './components/Heading';
```

Іменований експорт:

```tsx
// Оголошення у файлі компонента
export function Heading() {
  return <h1>Мої дисципліни</h1>;
}

// Імпорт в іншому файлі
import { Heading } from './components/Heading';
```

В одному модулі може бути один експорт за замовчуванням і декілька іменованих. Іменований імпорт використовує фігурні дужки та ім’я експорту. Імпорт за замовчуванням пишуть без фігурних дужок. У наступних кроках залишайте для `Heading` експорт за замовчуванням, щоб імпорти відповідали наведеним прикладам.

Це ES-модулі JavaScript: `import` та `export`. У цьому проєкті не використовуйте `require` і `module.exports`. Розширення `.mjs` для файлів компонентів також не потрібне.

Докладніше про відповідність імпорту й експорту: [Importing and Exporting Components](https://react.dev/learn/importing-and-exporting-components).

### Перевірка завдання 2

Сторінка повинна виглядати так само, як після завдання 1. Відмінність полягає в організації коду: `App` складає сторінку, а `Heading` описує привітання в окремому файлі. Збережіть у звіті код обох файлів на цьому етапі.

## 4 Завдання 3 Передавання типізованих props

### Крок 1 Визначте дані компонента

Привітання з іменем, записаним безпосередньо в JSX, підходить лише одній людині. Щоб компонент можна було повторно використати, передавайте ім’я, прізвище та групу з `App`.

Props — об’єкт вхідних даних компонента. Батьківський компонент `App` задає значення у JSX, а дочірній `Heading` отримує їх як параметр функції.

Для порівняння, у JavaScript компонент міг би виглядати так. Цей фрагмент лише ілюструє ідею; окремий `.jsx`-файл створювати не потрібно:

```jsx
function Greeting({ firstName }) {
  return <p>Привіт, {firstName}!</p>;
}
```

Варіант на TypeScript описує очікувані дані:

```tsx
type GreetingProps = {
  firstName: string;
};

function Greeting({ firstName }: GreetingProps) {
  return <p>Привіт, {firstName}!</p>;
}
```

`type GreetingProps` задає форму об’єкта, а `firstName: string` означає, що поле має бути рядком. TypeScript допоможе виявити передавання числа замість імені або відсутність потрібного поля ще під час розробки. Після перетворення в JavaScript анотацій типів немає: вони не створюють перевірку даних під час виконання. Дані із зовнішнього сервера або введення користувача потребують окремої перевірки.

### Крок 2 Оновіть Heading

Замініть увесь вміст `src/components/Heading.tsx` на:

```tsx
type HeadingProps = {
  firstName: string;
  lastName: string;
  group: string;
};

export default function Heading({
  firstName,
  lastName,
  group,
}: HeadingProps) {
  return (
    <header className="page-header">
      <h1>Привіт, {firstName} {lastName}!</h1>
      <p>Група: {group}</p>
    </header>
  );
}
```

Розберіть параметр функції:

- `{ firstName, lastName, group }` — деструктуризація об’єкта. Вона дістає три поля в окремі локальні змінні.
- `: HeadingProps` — тип усього об’єкта параметрів, а не частина деструктуризації.
- Усі три поля обов’язкові, бо біля їхніх назв немає `?`.
- Крапки з комою відокремлюють описи полів типу. Це не об’єкт зі значеннями: тут указано, які значення дозволені.

Альтернативою деструктуризації є параметр `props: HeadingProps` і звернення `props.firstName`. Обидва записи отримують той самий об’єкт. У роботі використовуйте деструктуризацію, як у повному прикладі.

Для такого опису можна також застосувати `interface HeadingProps { ... }`. Обидва способи підходять; додавати одночасно `type` та `interface` з однаковою назвою не потрібно.

### Крок 3 Передайте значення з App

Замініть `src/App.tsx` на:

```tsx
import Heading from './components/Heading';

export default function App() {
  return (
    <main className="page">
      <Heading
        firstName="Олена"
        lastName="Коваль"
        group="ІПЗ-21"
      />
    </main>
  );
}
```

Підставте власні дані. Тепер вони знаходяться у `App`, а `Heading` лише визначає спосіб їх відображення. Змінювати код `Heading` для іншої людини не потрібно.

Дочірній компонент не повинен присвоювати нові значення props або змінювати передані об’єкти. Props слід розглядати як доступні лише для читання в межах поточного відображення. Батьківський компонент може передати нові значення під час наступного оновлення.

### Крок 4 Перевірте користь TypeScript

Тимчасово змініть `firstName="Олена"` на `firstName={123}`. Відкрийте панель **View → Problems**: TypeScript має повідомити, що число не відповідає типу `string`. Поверніть рядок і переконайтеся, що помилка зникла.

Також тимчасово приберіть `group`. Перевірте повідомлення про відсутню обов’язкову властивість і поверніть її. Не залишайте навмисні помилки у фінальному коді та не приховуйте їх через `any` або `@ts-ignore`.

Текст у лапках є рядком. Значення `{123}` — числовий вираз. TypeScript перевіряє цю різницю, хоча браузер міг би відобразити і число, і рядок як текст.

### Крок 5 Повторно використайте компонент

Тимчасово додайте другий `<Heading ... />` усередині того самого `<main>`, передавши інші дані. Переконайтеся, що один компонент створює два різні привітання. Після перевірки залиште у фінальній сторінці лише власне привітання й один головний заголовок `h1`.

### Перевірка завдання 3

Ім’я, прізвище та група задаються в `App`, а не записані незмінним текстом усередині `Heading`. У файлі компонента є тип props. Панель Problems не містить помилок TypeScript.

Додаткові приклади доступні в документації [TypeScript у React](https://react.dev/learn/typescript) та [передавання props](https://react.dev/learn/passing-props-to-a-component).

### Крок 1 Створіть Subject

Створіть `src/components/Subject.tsx` і додайте:

```tsx
type SubjectProps = {
  subjectName: string;
  description: string;
  credits: number;
  teacher?: string;
};

export default function Subject({
  subjectName,
  description,
  credits,
  teacher,
}: SubjectProps) {
  return (
    <article className="subject">
      <h3>{subjectName}</h3>
      <p>{description}</p>
      <p>Кредити ЄКТС: {credits}</p>
      <p>Викладач: {teacher ?? 'Уточнюється'}</p>
    </article>
  );
}
```

`Subject` описує одну самостійну картку дисципліни. Елемент `article` підкреслює, що її вміст можна розглядати окремо від сусідніх карток. `className="subject"` пов’язує елемент із CSS-селектором `.subject`.

`subjectName` і `description` — рядки, `credits` — число. Числовий тип дозволяє надалі виконувати обчислення, але сам по собі не забороняє від’ємні значення: для навчальних даних задайте додатну кількість кредитів.

Знак `?` в `teacher?: string` робить поле необов’язковим. Якщо його не передати, значення дорівнюватиме `undefined`. Вираз `teacher ?? 'Уточнюється'` підставляє запасний текст, коли ліворуч `undefined` або `null`. Порожній рядок `""` не замінюється запасним текстом, тому для невідомого викладача просто не передавайте поле.

У прикладі наведено умовні дисципліни й імена. Підставте власні дані та дисципліни свого семестру.

Додайте до кожної картки кнопку, яка позначає дисципліну як вибрану та дозволяє скасувати вибір. Це локальна демонстрація: вона не надсилає заявку до університету й не зберігає вибір після перезавантаження сторінки.

### Крок 1 Створіть локальний стан

У `Subject.tsx` додайте на початку файлу:

```tsx
import { useState } from 'react';
```

Усередині функції `Subject`, перед `return`, додайте:

```tsx
const [isSelected, setIsSelected] = useState(false);

function handleToggle() {
  setIsSelected(current => !current);
}
```

State, або стан, — дані, які React зберігає між викликами компонента. Звичайна локальна змінна не забезпечує цього механізму: зміна через присвоєння не повідомляє React про необхідність оновити інтерфейс.

`useState(false)` задає початкове значення `false` і повертає пару: поточне значення `isSelected` та функцію зміни `setIsSelected`. TypeScript виводить тип `boolean` із початкового значення, тому окреме `useState<boolean>(false)` тут не обов’язкове.

Вираз `current => !current` обчислює наступне значення з попереднього: `false` стає `true`, а `true` — `false`. Не присвоюйте `isSelected = true`. Потрібно викликати setter, щоб React запланував новий рендер — повторне обчислення опису інтерфейсу.

Виклик `useState` розміщуйте на верхньому рівні тіла компонента, не всередині умови, циклу чи обробника натискання. Після setter змінна поточного виклику функції не змінюється миттєво: наступне значення компонент отримає під час наступного рендеру.

### Крок 2 Додайте кнопку

У JSX компонента `Subject` перед закривальним `</article>` додайте:

```tsx
<button
  type="button"
  className="select-button"
  onClick={handleToggle}
  aria-pressed={isSelected}
>
  Обрати дисципліну
</button>
<p role="status">
  {isSelected ? 'Дисципліну вибрано' : 'Дисципліну не вибрано'}
</p>
```

`onClick={handleToggle}` передає React функцію, яку потрібно виконати після натискання. Запис `onClick={handleToggle()}` викликав би її вже під час рендеру й міг би спричинити нескінченні оновлення.

`умова ? значення1 : значення2` — умовний оператор. Він вибирає текст залежно від `isSelected`. `aria-pressed` повідомляє стан кнопки-перемикача допоміжним технологіям, а `role="status"` позначає повідомлення про результат. Текст кнопки залишається сталим; поточний стан показує окремий абзац. Докладніше про кнопку-перемикач: [MDN — aria-pressed](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-pressed).

### 7.2 Перевірка типів і збірка

Зупиніть сервер через `Ctrl+C` або відкрийте ще один термінал у папці `lab3`. Виконайте:

```bash
npm run build
```

У React + TypeScript шаблоні команда збірки зазвичай має вигляд `tsc -b && vite build`: спочатку перевіряються типи, потім створюються файли для браузера. Перевірте поле `scripts` у своєму `package.json`. Якщо `build` запускає лише `vite build`, перед ним окремо виконайте:

```bash
npx tsc -b
```

`tsc` — компілятор TypeScript. Параметр `-b` враховує пов’язані конфігурації шаблону. У цій конфігурації TypeScript перевіряє код, а браузерну збірку готує Vite; окремий запуск `tsc App.tsx` не потрібний.

Сам факт роботи сторінки через `npm run dev` ще не доводить відсутності помилок типів: Vite перетворює TypeScript, але не виконує повну перевірку типів замість `tsc`. Детальніше: [Vite та TypeScript](https://vite.dev/guide/features.html#typescript).

Після успішної збірки з’являється папка `dist`. Її вміст генерується автоматично: не виправляйте помилки безпосередньо там. Змінюйте `src` і повторюйте збірку.

Перегляньте зібраний результат:

```bash
npm run preview
```

Відкрийте адресу з термінала та повторіть основні перевірки. `preview` показує останню збірку, а не автоматично збирає нові зміни. Якщо відредагували код, спершу знову виконайте `npm run build`. Сервер preview призначений для локальної перевірки, а не для публічного розгортання.

Якщо в `package.json` є команда `lint`, також виконайте:

```bash
npm run lint
```

Лінтер знаходить підозрілі конструкції та порушення правил коду. Він доповнює перевірку TypeScript, але не замінює перевірку поведінки сторінки.

## 8 Типові труднощі та їх усунення

### Не знайдено компонент або модуль

Перевірте, чи існує файл, чи правильно написано його назву та шлях. Для файлу `src/components/Subject.tsx` імпорт із `src/App.tsx` має бути `./components/Subject`. Також перевірте відповідність іменованого імпорту й експорту за замовчуванням.

### Компонент підкреслено через відсутні props

Наведіть курсор на підкреслення та прочитайте, якого поля бракує. Зіставте JSX із типом props. Наприклад, після додавання `semester: number` кожен `<Subject />` повинен отримувати числовий `semester`.

### Помилка через декілька сусідніх JSX-елементів

Помістіть їх в одну обгортку. Наприклад, заголовок і список дисциплін мають знаходитися всередині `<main>...</main>`. Два JSX-елементи поруч без обгортки не утворюють один вираз для `return`.

### Сторінка порожня або показує повідомлення про помилку

Спочатку прочитайте першу помилку у браузері та терміналі. Перевірте незакриті теги, дужки, імпорти й наявність `return`. Виправляйте помилки по одній: одна пропущена дужка може породити багато наступних повідомлень.

Не видаляйте контейнер `id="root"` у `index.html` і не змінюйте початкове підключення `App` у `main.tsx` без потреби.

### Стилі не застосовуються або екран залишається оформленим як шаблон

Перевірте імпорт `index.css` у `main.tsx`, точний збіг `className="subject"` і `.subject`, а також те, що початковий вміст `index.css` замінено. Переконайтеся, що в `App.tsx` не залишився імпорт старого `App.css`.

### Після збереження не видно змін

Перевірте, чи файл збережений, сервер працює, а браузер відкрив його актуальну адресу. Не плутайте вкладку `npm run dev` із вкладкою `npm run preview`: для preview потрібна нова збірка.

### Локальний стан скидається

Повне перезавантаження сторінки скидає стан, і це очікувано. Під час редагування коду сервер також може перезапустити частину інтерфейсу. Перевіряйте незалежність кнопок без зміни файлів між натисканнями. Якщо в `main.tsx` є `StrictMode`, у режимі розробки React може додатково викликати компоненти для перевірок; не видаляйте його лише через повторні діагностичні повідомлення. Докладніше: [React — StrictMode](https://react.dev/reference/react/StrictMode).

### PowerShell блокує npm.ps1

У VS Code виберіть профіль термінала **Command Prompt** і повторіть команду або використайте `npm.cmd` замість `npm` у PowerShell. Не вимикайте системні обмеження безпеки для всього комп’ютера заради запуску лабораторної.

## 9 Подання результатів

Підготуйте вихідний код проєкту та звіт.

До проєкту включіть `src`, `index.html`, `package.json`, `package-lock.json`, конфігураційні файли шаблону та власні ресурси, якщо ви їх додавали. Папки `node_modules` і `dist` до архіву з вихідним кодом не включайте: залежності відновлюються через `npm ci`, а результат збірки — через `npm run build`. `npm ci` використовує наявний узгоджений `package-lock.json`; якщо ви свідомо змінили залежності, спочатку оновіть lock-файл через `npm install`.

У звіті наведіть:

1. Тему й мету роботи, власне ім’я, прізвище та групу.
2. Код `App.tsx` і `Heading.tsx` після винесення компонента в окремий файл у завданні 2.
3. Остаточний код `App.tsx`, `Heading.tsx`, `Subject.tsx` і `index.css`.
4. Знімки фінальної сторінки на широкому та вузькому екрані.
5. Результат успішної перевірки типів і збірки.
6. Коротке пояснення того, які дані передаються через props і як TypeScript допоміг знайти помилку.
7. Якщо виконували додаткове завдання — знімок вибраної дисципліни та пояснення її локального стану.
8. Висновок про те, чого ви навчилися.

## 10 Захист лабораторної роботи

Захист відбувається усно з демонстрацією застосунку в браузері та коду в редакторі. Потрібно самостійно запустити проєкт, показати виконані завдання та пояснити будову програми.

Під час захисту будьте готові:

- показати, де оголошений кожен компонент і де він використовується;
- пояснити передавання props від `App` до `Heading` і `Subject`;
- пояснити обов’язкові й необов’язкові поля та числові значення в JSX;
- продемонструвати адаптивне оформлення;
- відповісти на контрольні питання;
- виконати невелику зміну в коді та пояснити її результат.

Приклади невеликих змін: додати ще одну дисципліну, змінити обов’язкове поле, додати новий рядок до всіх карток, змінити запасний текст для невідомого викладача або налаштувати кількість колонок. Якщо виконано додаткове завдання, потрібно також пояснити обробник натискання та незалежність стану карток.
