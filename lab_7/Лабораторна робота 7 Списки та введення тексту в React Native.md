# Лабораторна робота №7. Списки та введення тексту в React Native

## Мета роботи

Навчитися відображати колекції даних за допомогою `FlatList` і `SectionList`, типізувати записи та властивості компонентів, створювати керовані поля `TextInput` і налаштовувати поведінку форми під час відкриття клавіатури.

## Що має працювати наприкінці

Продовжте застосунок **Little Lemon** із лабораторної роботи №6. Підготуйте чотири варіанти основного вмісту екрана:

1. Меню зі стравами й цінами у `FlatList`.
2. Те саме меню, поділене на категорії, у `SectionList`.
3. Екран привітання з полем імені та привітанням, яке змінюється під час введення.
4. Навчальну форму входу з окремими полями email і пароля.

Шапка й підвал із №6 залишаються частинами застосунку. Списки прокручуються у доступній середній області, а форма дозволяє дістатися до полів під час відкриття клавіатури. Власні стилі оформлюються через `StyleSheet`, файли з JSX мають розширення `.tsx`.

Форма входу в цій роботі демонструє введення й локальну перевірку даних. Підключати сервер, створювати облікові записи або зберігати паролі не потрібно.

## Теоретичні відомості

### Дані, компоненти та типи

Масив об’єктів зберігає інформацію, а компоненти визначають, як її показати. Коли модель даних відокремлена від JSX, ту саму колекцію можна використати в різних списках, пошуку та наступних частинах застосунку.

У TypeScript тип описує, які поля має запис:

```ts
type Item = {
  id: string;
  title: string;
  duration: number;
};
```

`string` означає текст, `number` — число, а `Item[]` — масив записів. Якщо звернутися до неіснуючої властивості або передати текст замість числа, TypeScript повідомить про помилку. Файл `.ts` підходить для типів і даних без JSX; `.tsx` — для компонентів із розміткою.

### Як працює FlatList

`FlatList` отримує масив через `data`, а через `renderItem` — функцію, яка показує один запис. `keyExtractor` повертає його стабільний ключ.

Список підтримує вікно відображення навколо поточної позиції прокручування. Воно охоплює видимі рядки та частину сусідніх, щоб користувач міг плавно прокручувати колекцію. У звичайному `ScrollView` весь дочірній вміст створюється одразу. Для списку однотипних даних зручніше використати `FlatList`.

Приклад опису функції відображення:

```tsx
import type { ListRenderItem } from 'react-native';

const renderItem: ListRenderItem<Item> = ({ item }) => (
  <Text>{item.title}</Text>
);
```

Це фрагмент: для використання потрібні імпорт `Text` і визначення типу `Item`. `ListRenderItem<Item>` повідомляє TypeScript, який запис буде в `item`. Фігурні дужки в `({ item })` дістають цю властивість із аргументу функції, а `{item.title}` у JSX вставляє назву в текст.

Не вкладайте вертикальний `FlatList` у звичайний вертикальний `ScrollView`. Надайте самому списку доступну висоту через `flex: 1`, а додаткову шапку або опис за потреби передайте через `ListHeaderComponent`.

### Ключі, порожній стан і підвал

Ключ дозволяє React відрізняти записи після змін. Використовуйте `id`, який зберігається разом із даними, а не випадкове число чи індекс позиції. Після сортування або видалення запис зберігає той самий `id`, хоча його індекс змінюється.

`ListEmptyComponent` показує повідомлення, коли даних немає. `ItemSeparatorComponent` вставляє розділювач між рядками. `ListFooterComponent` є частиною прокручуваного вмісту; постійний підвал екрана слід розмістити поза списком.

### Як працює SectionList

`SectionList` отримує масив секцій через `sections`. Кожна секція має `data` — масив записів. Назву групи можна зберігати у власній властивості `title`, а її ключ — у `key`.

`renderItem` описує рядок, `renderSectionHeader` — заголовок групи. Властивість `stickySectionHeadersEnabled` керує закріпленням заголовків під час прокручування. Установіть її явно: так бажана поведінка буде зрозумілою на iOS і Android. За замовчуванням закріплення ввімкнене в iOS, але вимкнене в Android.

### Кероване поле TextInput

У керованому полі `value` береться зі стану, а `onChangeText` передає новий текст у setter:

```tsx
const [name, setName] = useState('');

<TextInput value={name} onChangeText={setName} />
```

Ці рядки розташовують усередині компонента; `useState` імпортують із `react`, `TextInput` — із `react-native`. Під час введення стан змінюється, React повторно обчислює компонент, і поле отримує нове `value`. Початковий порожній рядок дозволяє TypeScript вивести тип стану як `string`.

`placeholder` є підказкою і зникає після введення. Додайте постійний підпис через `Text` та `accessibilityLabel`, щоб призначення поля залишалося зрозумілим.

`keyboardType="email-address"` добирає зручну клавіатуру, але не перевіряє email. `secureTextEntry` маскує пароль, але не шифрує його. Для пароля використовуйте однорядкове поле, а не `multiline`.

### Клавіатура та форма

`KeyboardAvoidingView` допомагає змінювати відступи або висоту контейнера, коли відкривається клавіатура. `ScrollView` усередині дозволяє дістатися до вмісту короткої форми, який не вмістився у зменшеній області.

Для такої форми можна почати з `behavior={Platform.OS === 'ios' ? 'padding' : 'height'}` і перевірити результат на своєму пристрої. Android також може змінювати розмір вікна автоматично; якщо відступ виходить подвійним, перевірте налаштування застосунку й поведінку контейнера. Не покладайтеся на фіксовану висоту екрана.

`keyboardShouldPersistTaps="handled"` дозволяє елементам усередині прокручуваної форми обробляти натискання з відкритою клавіатурою. `keyboardDismissMode="on-drag"` закриває її після початку прокручування. `Keyboard.dismiss()` закриває клавіатуру явно.

### Завдання 1. Відобразіть меню через FlatList

1. Створіть `MenuItemRow` із властивістю `item: MenuItem`.
2. Покажіть назву страви й її ціну в одному рядку. Для ціни можна використати `item.price.toFixed(2)` і додати «грн».
3. У `MenuFlatScreen` імпортуйте дані, компонент рядка, `FlatList` та `StyleSheet`.
4. Передайте колекцію через `data`, компонент рядка — через `renderItem`, ідентифікатор — через `keyExtractor`.
5. Додайте заголовок списку, розділювачі та повідомлення для порожньої колекції.

Основний фрагмент списку всередині `return`:

```tsx
<FlatList<MenuItem>
  style={styles.list}
  contentContainerStyle={styles.content}
  data={menuItems}
  keyExtractor={(item) => item.id}
  renderItem={({ item }) => <MenuItemRow item={item} />}
  ListEmptyComponent={<Text>Меню поки порожнє.</Text>}
/>
```

Це фрагмент JSX, а не повний файл. Підключіть `Text`, тип `MenuItem` через `import type`, дані та власний компонент. У `styles.list` задайте `flex: 1`, а у `styles.content` — відступи.

Щоб вирівняти назву й ціну, задайте контейнеру рядка `flexDirection: 'row'`. Назві віддайте `flex: 1`, а між текстами залиште відступ. Перевірте довгу назву: вона може переноситися, але не повинна перекривати ціну. `toFixed(2)` повертає рядок із двома десятковими знаками; вихідна ціна в масиві залишається числом.

Для заголовка використайте `ListHeaderComponent`, для розділювача — `ItemSeparatorComponent`. Це дозволяє оформити список без зовнішнього `ScrollView`. Стилі називайте за призначенням: `row`, `name`, `price`, `separator`, а не `style1`.

Перевірте прокручування до останньої страви. Тимчасово передайте порожній масив у `data`, перевірте повідомлення, потім поверніть дані. Постійний підвал застосунку має залишатися поза списком.

### Завдання 2. Відобразіть те саме меню через SectionList

Створіть `MenuGroupedScreen`, використовуючи той самий `MenuItemRow`. Підготуйте секції з існуючих даних, щоб не підтримувати другу окрему копію меню:

```tsx
import type { SectionListData } from 'react-native';
import type { CategoryInfo, MenuItem } from '../types/menu';
import { categories, menuItems } from '../data/menu';

const sections: SectionListData<MenuItem, CategoryInfo>[] = categories.map(
  (category) => ({
    ...category,
    data: menuItems.filter((item) => item.category === category.key),
  }),
);
```

`map` створює по одному об’єкту секції для кожної категорії. `...category` копіює її `key` та `title`. `filter` залишає в `data` лише страви потрібної категорії. Така структура відокремлює групування від відображення.

У JSX додайте `SectionList<MenuItem, CategoryInfo>`. Передайте `sections`, задайте `keyExtractor={(item) => item.id}` і використайте компонент рядка в `renderItem`. Заголовок секції отримуйте так:

```tsx
renderSectionHeader={({ section }) => (
  <Text style={styles.sectionTitle}>{section.title}</Text>
)}
```

Установіть `stickySectionHeadersEnabled={true}`. Дайте заголовку непрозоре тло, щоб прокручувані страви під ним не заважали читанню. Перевірте також поведінку зі значенням `false`, а потім залиште бажаний варіант.

Результат має містити всі чотири категорії, назви й ціни страв. `id` страв не змінюються після групування, а `key` категорій відрізняють самі секції. Збережіть також працездатний варіант із `FlatList`.

### Завдання 3. Додайте введення імені на екрані привітання

У `WelcomeScreen` імпортуйте `useState` із `react`, а `TextInput` — із `react-native`. Усередині функції компонента додайте стан:

```tsx
const [name, setName] = useState('');
```

Додайте постійний підпис «Ваше ім’я» і кероване поле з підказкою, `value`, `onChangeText` та `accessibilityLabel`. Під полем показуйте «Введіть ім’я» для порожнього значення і «Вітаємо, …!» для заповненого.

Підказка для вибору тексту:

```tsx
<Text>
  {name.trim() ? `Вітаємо, ${name.trim()}!` : 'Введіть ім’я.'}
</Text>
```

`trim()` прибирає пробіли на краях. Тому введення лише пробілів не вважається змістовним ім’ям. Не змінюйте текст у самому полі через `trim` після кожного символу: це може заважати вводити кілька слів. У цьому фрагменті очищене значення використовуємо лише для привітання.

Текстовий вміст екрана можна розмістити у `ScrollView`. Якщо у №6 він прокручувався завдяки контейнеру в `App.tsx`, перенесіть прокручування у `WelcomeScreen`, оскільки спільна оболонка тепер має підходити також для списків. За потреби використайте `KeyboardAvoidingView`, як описано нижче для форми.

Перевірте введення, видалення, кілька слів і пробіли. Поясніть, як зміна одного стану оновлює поле та привітання.

### Завдання 4. Створіть навчальну форму входу

У `LoginScreen` створіть окремі стани для email і пароля:

```tsx
const [email, setEmail] = useState('');
const [password, setPassword] = useState('');
```

Розмістіть заголовок «Вхід до Little Lemon», коротке пояснення та два підписані поля. Кожне поле має власні `value` і `onChangeText`, щоб введення в одне поле не змінювало інше.

Для email задайте `keyboardType="email-address"`, `autoCapitalize="none"` та `autoCorrect={false}`. Для пароля задайте `secureTextEntry`, `autoCapitalize="none"` та `autoCorrect={false}`. Не відображайте значення пароля у текстовій підказці та не виводьте його в консоль.

Додайте ненав’язливі повідомлення про стан форми: чи заповнено email, чи містить він приблизно коректний формат, чи введено пароль. У цій роботі не створюйте повідомлення «Користувач авторизований»: без серверної перевірки облікових даних це було б неправильним результатом.

Для простої навчальної перевірки email можна використати:

```ts
function isEmailFormatValid(value: string): boolean {
  return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value.trim());
}
```

Ця функція перевіряє лише приблизний формат, а не існування поштової скриньки. Покажіть результат перевірки після втрати фокуса або після того, як поле містить введення. Пароль перевіряйте як непорожній рядок; не обрізайте його пробіли автоматично, оскільки вони можуть бути частиною значення.

Зручна структура компонента форми:

```tsx
<KeyboardAvoidingView
  style={styles.screen}
  behavior={Platform.OS === 'ios' ? 'padding' : 'height'}
>
  <ScrollView
    contentContainerStyle={styles.form}
    keyboardShouldPersistTaps="handled"
    keyboardDismissMode="on-drag"
  >
    {/* Заголовок, підписи, поля та повідомлення перевірки. */}
  </ScrollView>
</KeyboardAvoidingView>
```

Імпортуйте `KeyboardAvoidingView`, `ScrollView` і `Platform` із `react-native`. Для `screen` задайте `flex: 1`, для `form` — відступи й за потреби `flexGrow: 1`. Вставте свої поля замість коментаря.

Для останнього однорядкового поля можна задати `returnKeyType="done"` і `submitBehavior="blurAndSubmit"`. Якщо користувач натисне відповідну клавішу, фокус із поля буде прибрано. Підпис клавіші й доступність такої дії залежать від клавіатури пристрою; прокручування також має залишатися способом дістатися до всього вмісту.

Якщо перевіряєте й нормалізуєте email у `onBlur`, спочатку збережіть `const normalized = email.trim()`, а потім використайте `normalized` для `setEmail` і перевірки. Setter не змінює одразу значення змінної `email` у поточному обробнику.

На цьому етапі результатом є форма введення та локальна перевірка. Обробку дії входу через кнопку, серверну взаємодію й навігацію вивчатимемо окремо.

### Додаткове завдання. Пошук у меню

На екрані `MenuFlatScreen` додайте поле пошуку над списком. Зберігайте запит у `useState`, а видимі страви обчислюйте з нього:

```tsx
const [query, setQuery] = useState('');
const normalizedQuery = query.trim().toLocaleLowerCase('uk-UA');
const visibleItems = menuItems.filter((item) =>
  item.name.toLocaleLowerCase('uk-UA').includes(normalizedQuery),
);
```

Передайте `visibleItems` у `data`. `filter` створює новий масив, початкова колекція не змінюється. Порожній запит показує всі страви, а запит без збігів — `ListEmptyComponent`. Окремий стан для відфільтрованого масиву тут не потрібен.

Поле можна розмістити над `FlatList` у контейнері `View`, а списку віддати `flex: 1`. Перевірте пошук із великими й малими літерами та повернення всіх записів після очищення.

## Перевірка результату

Виконайте у папці проєкту:

```bash
npx tsc --noEmit
```

Виправте всі помилки типів. Потім перевірте застосунок на телефоні або в емуляторі:

- Обидва списки показують ті самі страви та ціни; у згрупованому варіанті є чотири категорії.
- Можна прокрутити до останнього запису; шапка й постійний підвал не перекривають вміст.
- Усі ключі стабільні, а консоль не показує попереджень про повторні ключі чи вкладені вертикальні списки.
- Порожній масив показує зрозуміле повідомлення.
- Поле імені оновлює привітання, а порожнє значення й пробіли обробляються коректно.
- Email і пароль мають окремий стан; пароль маскується.
- Під час відкриття клавіатури можна дістатися до полів і прочитати повідомлення.
- Довгі назви й збільшений системний шрифт не перекривають ціну та не обрізають важливий текст.

Збережіть усі вихідні файли та інструкцію запуску. Якщо передаєте папку проєкту, залиште `package.json` і файл блокування залежностей; `node_modules` додавати не потрібно.

## Типові помилки

| Помилка | Як виправити |
| --- | --- |
| Вертикальний список вкладено у `ScrollView` | Залиште списку власне прокручування; додатковий вміст передавайте через його властивості або розміщуйте поруч. |
| Страви не мають `id` у секціях | Використайте початкові об’єкти із ключами; не перетворюйте їх лише на рядки назв. |
| Ключ побудовано з індексу або випадкового числа | Поверніть стабільний `item.id`. |
| `item` отримав неявний тип `any` | Задайте тип елемента `FlatList<MenuItem>` або використайте `ListRenderItem<MenuItem>` для окремої функції. |
| Поле не реагує на введення | Перевірте зв’язок `value` та `onChangeText` із тим самим станом. |
| Email і пароль змінюються одночасно | Створіть два незалежні стани та обробники. |
| Клавіатура приховує нижні поля | Перевірте структуру `KeyboardAvoidingView`, прокручування й `flex: 1`. |
| Перевірка email бачить значення до `trim` | Використайте локальну змінну нормалізованого тексту для setter і перевірки. |

Захист усний, із демонстрацією застосунку. Покажіть чотири компоненти екрана, прокручування списків, групування, введення імені та поведінку форми з відкритою клавіатурою. Поясніть структуру файлів, типи даних, ключі записів, взаємодію props і стану.

Будьте готові відповісти на контрольні питання та внести мінімальну зміну в код: додати страву до наявної категорії, змінити формат ціни, вимкнути закріплення заголовків, змінити текст підказки або скоригувати перевірку форми. Поясніть, які компоненти оновляться після зміни й чому.

Контрольні питання:

1. Чим `FlatList` відрізняється від `ScrollView`?
2. Що означає віртуалізація? Чому список може готувати невидимі сусідні рядки?
3. Яку роль виконують `data`, `renderItem` і `keyExtractor`?
4. Чому `id` підходить для ключа краще за індекс змінюваної колекції?
5. Як із одного масиву меню утворити секції?
6. Чим відрізняються ідентифікатор страви й ключ секції?
7. Для чого потрібні типи `MenuItem` і `MenuCategory`?
8. Як працює кероване поле `TextInput`?
9. Чому тип клавіатури не гарантує коректного email?
10. Що робить `secureTextEntry` і чого ця властивість не забезпечує?
11. Як `KeyboardAvoidingView` і прокручування допомагають працювати з формою?
12. Чим локальна перевірка форми відрізняється від авторизації на сервері?
